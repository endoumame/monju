# herdr でメンバーを呼ぶ

herdr のペインの中で動いているとき（環境変数 `HERDR_ENV` が `1`）の呼び出し方です。メンバーは、別のペインで起動した別のエージェントとして動きます。

## 最初に確かめること

- `HERDR_ENV` が `1` でなければ、このファイルの手順は使いません。`references/fallback.md` に進んでください。
- ここのコマンドは herdr 0.9.5 のCLIリファレンスをもとに書いています。**版が違ってコマンドが通らないときは、`herdr <コマンド> --help` か、`herdr --skill` が出力する公式スキルの書き方に従ってください。** herdr の公式スキルが入っているなら、コマンドの書き方はそちらを優先します。
- 自分がいるペインのIDは環境変数 `HERDR_PANE_ID` でわかります。
- ペインの中から `herdr` 本体を起動し直さないでください。入れ子の起動は止められます。

## 流れ

### 1. 依頼文を書類として置く

依頼文は長いので、コマンドの引数として渡しません。引用符の扱いで壊れたり、長すぎて拒否されたりします。作業用の置き場に書類として置き、メンバーには「それを読んで」とだけ伝えます。

```
${TMPDIR:-/tmp}/monju-<議題の短い名前>/
├── <役割その1>/brief.md
├── <役割その2>/brief.md
└── <役割その3>/brief.md
```

置き場はプロジェクトの外に作ります。プロジェクトの中に作ると、変更として拾われたり、ほかのメンバーが調査の途中で読んでしまったりします。

`brief.md` は `members.md` のひな形で書き、「決まり」の下に次を足します。

```
- 回答は <この役割のフォルダー>/answer.md に書いてください。書いてよいのはこの書類だけです。
- monju-<議題の短い名前>/ の中にあるほかのフォルダーは読まないでください。
```

### 2. メンバー用のタブを作る

メンバーの作業がユーザーの目に入ると、読む量が増えてしまいます。ユーザーが見ているタブは分割せず、別のタブにまとめます。

```bash
herdr tab create --label monju --cwd <プロジェクトの場所> --no-focus
herdr pane split <1人目のペインID> --direction right --no-focus
herdr pane split <1人目のペインID> --direction down --no-focus
```

新しいペインのIDは、返ってきた結果から読みます（`tab create` は `.result.root_pane.pane_id`、`pane split` は `.result.pane.pane_id`）。ペインが閉じるとIDが変わることがあるので、控えたIDを使い回さず、必要なら `herdr pane list` で確かめます。

### 3. エージェントを起動する

```bash
herdr agent start monju-<役割> --kind <種類> --pane <ペインID>
```

- `--kind` に指定できる種類（`claude`、`codex` など）は `herdr agent start --help` で確かめる。
- 使えるコマンドが2種類以上入っているなら、少なくとも1人は進行役と別の種類で起動する。入っているかどうかは `command -v <コマンド名>` で確かめる。
- 1種類しかなければ全員を同じ種類で動かし、意見が似やすいことを地図を出すときに一言伝える。

### 4. 依頼を送る

```bash
herdr agent prompt monju-<役割> "<この役割のフォルダー>/brief.md を読み、その指示に従ってください。"
```

3人分を続けて送ります。ここでは完了を待ちません。待つと1人ずつの順番になり、並行して動きません。

送り終えたら、いつもの問い（「戻るまでに、もしよければ: 3人の意見はどこで割れると思いますか？」）を添えて、**いったん発言を終えます。** herdr では、待っているあいだ進行役の手がふさがるので、ユーザーの返事を受け取ってから待ちに入ります。答えがなくてよい旨（「なければ『なし』で」）も添えてください。

### 5. 待つ

ユーザーの返事を受けてから、メンバーごとに待ちます。

```bash
herdr agent wait monju-<役割> --timeout 600000
```

`--timeout` は必ずつけます。省くといつまでも待ち続けます。指定しなければ、手が空いた、終わった、止まった、のどれかで戻ります。戻ったら `herdr agent list` で状態を見ます。

| 状態 | すること |
|---|---|
| 終わった（`done`、`idle`） | 回収へ進む |
| 止まった（`blocked`） | 権限の確認などで人の操作を待っている。ユーザーに「『<役割>』が確認待ちで止まっています。monju のタブを見てください」と伝え、もう一度待つ |
| 時間切れ | そのメンバーを待たずに、残りの回答で地図を出す。誰が欠けたかを伝える |

### 6. 回収する

`answer.md` を読みます。なければ、ペインの出力から拾います。

```bash
herdr pane read <ペインID> --source recent-unwrapped --lines 80
```

ペインの出力には画面の飾りや途中経過が混ざります。【立場】【根拠】【気になる所】【未確認】【自信】に当たる部分だけを抜き出してください。形式を守っていなくても、やり直させずに使います。

### 7. 片づける

メンバーのタブは、合議が続いているあいだは残します。ユーザーが回答の全文を読みたくなったときに見られるようにするためです。地図を出すときに、最初の1回だけ「3人の回答全文は monju のタブで読めます」と伝えます。

締めるか持ち越すかが決まったら、メンバーのペインを閉じ、置き場を消します。

```bash
herdr pane close <ペインID>
rm -rf "${TMPDIR:-/tmp}/monju-<議題の短い名前>"
```

## 2巡目

同じペインのメンバーに、新しい依頼文（`brief-2.md`）を置いて送ります。メンバーは自分の1巡目の調査を覚えているので、背景を書き直す必要はありません。足すのは「ここまでにわかったこと」と「いまの論点」だけです。ほかのメンバーの回答や、ユーザーの傾きは書きません。

1巡目にいなかった顔ぶれを入れるときは、ペインを1つ足して起動します。

## 寄り道

herdr にはスレッドのフォークがありません。問いの意味を確かめる寄り道が長引いたら、新しいペインで別のエージェントを起動し、そこで聞くことをユーザーに勧めます。わかったことだけをユーザーが持ち帰り、寄り道のペインは閉じます。進行役の文脈には寄り道のやりとりを入れません。

## 気をつけること

- **ユーザーのペインの表示を奪わない。** タブやペインを作るときは `--no-focus` をつける。
- **ユーザーが開いているほかのペインに入力を送らない。** 送り先は、自分が作った `monju-` で始まる名前のメンバーだけにする。
- **メンバーは読み取り専用。** 書いてよいのは自分の `answer.md` だけ。
- **結果は書類で受け取る。** ペインの出力を読むのは、書類がないときの最後の手段にする。
