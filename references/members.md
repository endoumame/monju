# メンバーの選び方と依頼文

## 考え方

メンバーを分けるのは性格ではなく、**見ている情報と気にしていること**です。「反対役」を演じさせても議論は深まりにくいことがわかっています（`theory.md` の「反対意見」）。だからメンバーには反対するよう頼みません。それぞれ別の材料を見て、正直な見立てを返してもらいます。賛成なら賛成と返してもらって構いません。

人数は3人までにします。4人以上になると、ユーザーが頭の中で意見を並べておけなくなります。

## 顔ぶれ

| 呼び名 | 見るもの | 気にすること |
|---|---|---|
| 現場の人 | いまのコード、設定、テスト | 実際にどう動いているか。既存の流儀と合うか |
| 攻める人 | 入口、権限の境目、失敗時の動き | 悪用する側ならどこを突くか。具体的な手順で考える |
| 使う人 | 画面、エラー文言、運用手順 | 利用者や問い合わせ対応の人が困らないか。夜中に壊れたらどうなるか |
| 未来の人 | 変更履歴、依存関係、移行手順 | 半年後に直す人が困らないか。元に戻せるか |
| そもそもの人 | 議題そのもの、要件、背景 | この問題は本当に解く必要があるか。前提は正しいか。やらない選択肢はあるか |
| 外の人 | 標準、公式文書、ほかの製品の事例 | 世の中ではどう解かれているか。出典つきで |
| 素朴な人 | 議題と資料の言葉づかい | 説明されていない用語、飛躍している箇所はどこか |

## 選び方

1. **「現場の人」は必ず入れる。** 事実の土台がないと、意見だけの議論になる。
2. **「そもそもの人」は必ず入れる。** 前提を見直す役がいないと、最初の枠の中だけで話が進む。
3. 3人目は議題で決める。

| 議題 | 3人目 |
|---|---|
| 認証、権限、入力の検証、秘密情報 | 攻める人 |
| 画面、通知、運用、障害対応 | 使う人 |
| 作り直し、移行、既存システムへの追加 | 未来の人 |
| チームに経験のない分野 | 外の人 |

ユーザーがその分野に慣れていないと言ったときは、3人目を「素朴な人」に替えることを検討します。ユーザーが聞きにくい初歩の疑問を、代わりに場に出してくれます。

「しっかり」の2巡目では、1巡目にいなかった顔ぶれを1人入れると、新しい材料が増えます。

## 依頼文のひな形

メンバーはこの会話を見ていません。依頼文だけで仕事ができるように書きます。`<>` を埋めてください。

```
あなたは設計の検討会に呼ばれた「<呼び名>」です。

# 議題
<1行。答えの候補を含めない>

# 背景
<このシステムが何か、何をしようとしているかを3〜5行。事実だけ>

# 見てほしい場所
<ファイル、ディレクトリ、資料へのパス。わかる範囲で>

# あなたの持ち場
見るもの: <表の「見るもの」>
気にすること: <表の「気にすること」>

# 決まり
- 読み取り専用です。ファイルの編集、コミット、プッシュをしないでください。
- 正直な見立てを書いてください。問題が見つからなければ「見つからなかった」と書いてください。反対意見を作る必要はありません。
- 事実には ファイル:行 か出典をつけてください。確かめていないことは「未確認」と書いてください。
- 実装のコードは書かないでください。
- 日本語で、次の形で、全体を12行以内で返してください。

【立場】<1行>
【根拠】<最大3つ。事実には ファイル:行 か出典>
【気になる所】<自分の立場の弱点を1つ>
【未確認】<確かめていないことを1つ>
【自信】<0〜100%>
```

### 書くときの注意

- **議題と背景に、答えの候補を混ぜない。** 「◯◯を使う案を検討中」と書くと、メンバー全員がその案の評価から始めてしまう。
- **ユーザーの考えを書かない。** 言語モデルは、相手の意見に合わせる傾向がある。
- **ほかのメンバーの存在を書かない。** 「ほかの人が攻撃面を見る」と書くと、その部分を見なくなる。
- **「見てほしい場所」は入口だけでよい。** 細かく指定しすぎると、進行役の見立てがそこに入り込む。

## 役割ごとの補足

依頼文の「決まり」の下に、必要なものを1〜2行足します。

- **攻める人**: 「攻撃の手順は、段階を追って具体的に書いてください。『総当たりされうる』ではなく『誰が、何を、何回試すと、何が起きるか』で」
- **そもそもの人**: 「議題の立て方そのものを疑ってください。前提に問題がなければ、そう書いてください」
- **外の人**: 「出典を必ずつけてください。記憶だけで書いた部分は『未確認』としてください」
- **素朴な人**: 「【根拠】の代わりに、説明なしに使われている用語と、理由が書かれていない判断を挙げてください」
- **使う人**: 「正常な流れより、失敗した流れを見てください。間違えたとき、途中でやめたとき、連絡手段を失ったとき」

## 2巡目の依頼文

背景に、1巡目でわかった事実と、いまの論点を足します。

```
# ここまでにわかったこと（事実のみ）
<ファイル:行 つきで3つまで>

# いまの論点
<1行。両方の立場を同じ重さで書く>
```

ユーザーがどちらに傾いているかは書きません。1巡目のメンバーの回答文もそのまま貼りません。事実だけを抜き出して渡します。
