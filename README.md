# monju

結論を急がずに、複数の視点で設計を話し合うためのスキルです。AIが推奨案を出し、人がそれを承認する、という流れを避け、使う人自身が発言者の1人として考え抜けるように進行します。名前は「三人寄れば文殊の知恵」から取りました。

## 何をするか

1. 先に、あなたがいまの考えを書く
2. 視点の違うメンバー3人が、互いの意見もあなたの考えも見ずに調べる
3. 進行役が、意見の一致点と割れた点を「地図」にして出す
4. 割れた点を1つずつ、短いやりとりで話す
5. あなたが自分の言葉で決める。決めずに持ち越してもよい

進行役は案を選びません。聞かれれば意見は言いますが、あなたの選択を先に聞きます。

## 入れ方

このリポジトリを、使っているプロバイダーのスキル置き場に取得します。

| プロバイダー | 置き場 |
|---|---|
| Claude Code | `~/.claude/skills/monju/` |
| Codex など | `~/.agents/skills/monju/` |

```bash
git clone https://github.com/endoumame/monju ~/.claude/skills/monju
```

更新するときは、置き場で `git pull` を実行します。

T3 Code では、入力欄で `$` を打つとスキルの一覧が出ます。プロジェクト内（`<プロジェクト>/.claude/skills/`）に置いたスキルが一覧に出ない不具合が過去に報告されているので、出ないときは利用者単位の置き場を試してください。

メンバーの呼び出し方は、環境に合わせて自動で切り替わります。

| 環境 | 呼び出し方 |
|---|---|
| T3 Code v0.1.0 以降 | `delegate_task` で子スレッドとして呼ぶ |
| herdr | 別のタブにペインを作り、そこでエージェントを起動して呼ぶ |
| それ以外 | サブエージェントで呼ぶ。それもできなければ進行役が1人で書く簡易版 |

herdr では、herdr の公式スキル（`npx skills add herdrdev/herdr --skill herdr -g`）も入れておくと、版によるコマンドの違いを吸収しやすくなります。

## 使い方

```
monju。<迷っていること>
```

規模は言葉で指定できます。

| 言い方 | 規模 |
|---|---|
| 「軽く」「さっと」 | 軽め。メンバーを呼ばない |
| 指定なし | ふつう。メンバー3人 |
| 「しっかり」 | しっかり。事前検死とチーム向けの論点メモつき |

途中で使える言葉です。

| 言葉 | 起きること |
|---|---|
| 「地図」 | 最新の論点の一覧を出す |
| 「そもそも」 | 前提の見直しに入る |
| 「締める」 | 決定の4行を書く段階に入る |
| 「持ち越す」 | 決めずに終える |
| 「で、どれがいい？」 | 先にあなたの選択を聞かれ、そのあと進行役が一意見として答える |

## 試し方

最初は、すでに答えを知っている小さな議題で試すと、進行の癖が見やすくなります。次の3つを順に試してください。

1. **軽め**: 「monju、軽く。この設定値を環境変数にするか設定ファイルにするか」
2. **ふつう**: 最近AIに任せて決めた設計を1つ、もう一度かける
3. **しっかり**: いま実際に迷っている、認証や権限に関わる判断

試したあと、次の点を見てください。

| 見る点 | 期待する姿 |
|---|---|
| 進行役が案を選んだか | 選んでいない。「おすすめ」と言っていない |
| 最初にあなたの考えを聞いたか | メンバーを呼ぶ前に聞いている |
| 1回の発言の長さ | 8行以内 |
| 問いの数 | 1回に1つ |
| 問いの意味がわかったか | 理由と具体例がついている |
| 地図は役に立ったか | 論点を覚えておかなくて済んだ |
| メンバーの意見は割れたか | 割れなければ、割り当てるプロバイダーを見直す |
| 締めの4行を自分で書けたか | 書けなければ、まだ決める段階ではなかった |
| 終わったあと、人に説明できるか | できれば、このスキルは働いている |

最後の1行が一番大事な確認です。

## 調整する所

使ってみて合わなければ、次の値を変えてください。

| 変えたいこと | 場所 |
|---|---|
| 発言の長さの上限（8行） | `SKILL.md` の「七つの約束」3 |
| メンバーの人数（3人） | `references/members.md` の「考え方」 |
| 顔ぶれの追加（データベースに詳しい人、など） | `references/members.md` の「顔ぶれ」 |
| 「しっかり」に切り替わる話題 | `SKILL.md` の「規模」 |
| 続けるかを聞く間隔（5〜6往復） | `SKILL.md` の「話す」 |
| 決定メモの項目 | `assets/decision-memo.md` |

## 知っておいてほしいこと

- **面倒です。** 先に自分で書く、短いやりとりを重ねる、自分の言葉で締める、という手間は意図したものです。AIへの過信を減らす仕掛けは、効くものほど使い手の評価が低い、という研究があります。急ぎの小さな判断には使わないでください。
- **費用がかかります。** メンバー3人分の使用量が加わります。
- **人間の議論の代わりにはなりません。** メンバーは、コードに書かれていない経緯や事情を知りません。重い判断は、ここで論点を整理してからチームに持ち込んでください。
- **効果は確かめていません。** 進め方は認知科学と心理学の知見にもとづいていますが、このスキル自体を試した結果ではありません。根拠と限界は `references/theory.md` にまとめています。
